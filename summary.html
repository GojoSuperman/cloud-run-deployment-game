1. 오늘 배운 핵심 개념

☁️ Cloud Run의 역할

  • Cloud Run = 로드밸런서 역할. 서비스 주소로 온 요청을 리비전으로 분배
  • 리비전 = 배포할 때마다 만들어지는 이미지+설정 한 벌
  • 트래픽 설정 = 어느 리비전에 요청의 몇 %를 보낼지 정한 것

Cloud Run이 트래픽 설정에 따라 리비전 사이에 요청을 분배합니다

🔄 기본 배포 순서

STEP 1
새 리비전 인스턴스 켜기
새 이미지와 설정으로 인스턴스를 시작합니다
STEP 2
스타트업 프로브 통과 확인
앱이 요청을 받을 준비가 됐는지 확인합니다
STEP 3
트래픽 100% 새 리비전으로
프로브 통과 후 모든 요청을 새 리비전으로 보냅니다
STEP 4
이전 인스턴스에 SIGTERM
이전 리비전의 인스턴스에 종료 신호를 보냅니다
STEP 5
10초 그레이스풀 셧다운 후 종료
진행 중인 요청을 마무리한 뒤 인스턴스를 종료합니다

2. 배포 방식

🏷️ 태그 URL과 블루그린

  • --no-traffic으로 0% 배포, --tag green으로 태그 URL 생성
  • 태그 URL = https://green---서비스명.run.app (트래픽과 무관하게 접근)
gcloud CLI
$ gcloud run services update friend-agent-staging \ --update-env-vars "BANNER=GREEN" \ --no-traffic --tag green ✓ 태그 URL: https://green---friend-agent-staging-xxx.run.app

⚖️ 배포 방식 비교

기본 배포

준비되면 바로 100%

+ 간단 - 롤백 느림

블루그린

0% → 태그 확인 → 100%

+ 빠른 롤백 - 수동 확인 필요

카나리

10% → 50% → 100%

+ 위험 최소화 - 요청 많아야 의미

3. 트래픽 고정과 롤백

📌 트래픽 고정의 함정

  • 롤백/카나리 → 트래픽이 특정 리비전에 고정
  • 새 배포해도 0% → "배포 성공인데 사용자는 이전 버전"
  • 해결: update-traffic --to-latest
트래픽 고정 해제
$ gcloud run services update-traffic --to-latest ✓ 트래픽이 가장 최근 리비전을 따라가게 설정됨

⚡ 롤백 신호 5가지

신호무엇을 보나롤백 기준
오류율5xx 응답 비율이전 리비전의 2배 이상
지연 시간p95 응답 시간1초 이상
핵심 기능로그인, 메시지 전송한 번이라도 실패
인스턴스 상태시작 실패, 메모리 초과이전에 없던 일
사용자/비용신고, API 비용갑자기 늘어남

5. 자동 배포 파이프라인

🔄 머지 한 번으로 무중단 배포

STEP 1
PR 머지 & 배포 승인
코드 리뷰 후 머지하면 워크플로가 시작됩니다
STEP 2
이미지 빌드 & 0% 배포 + 태그
새 이미지를 빌드하고 트래픽 없이 배포, 태그 URL 생성
STEP 3
스모크 테스트 (태그 URL)
/health 정상 + /version 커밋 일치 확인
STEP 4
트래픽 100% 전환
테스트 통과 후 모든 트래픽을 새 리비전으로 이동
STEP 5
(문제 시) 원클릭 롤백
rollback.yml로 이전 리비전에 트래픽 100% — 몇 초 만에 완료

🧪 스모크 테스트

  • 태그 URL로 확인 (서비스 주소는 이전 리비전이 답하므로)
  • /health 정상 + /version 커밋 일치 확인
  • 실패 → 워크플로 실패 → 전환 안 함

⏪ 원클릭 롤백

  • rollback.yml + workflow_dispatch
  • 이전 리비전으로 트래픽 100%
  • 몇 초 만에 완료

6. 한 장 요약

#핵심
1Cloud Run이 로드밸런서: 리비전 사이 트래픽 설정으로 요청 배분
2스타트업 프로브를 /health로 → 준비 늦어도 실패 0건
3태그 URL로 0% 리비전을 사용자 영향 없이 확인
4롤백 = 트래픽 설정만 바꿈 → 몇 초
5트래픽 고정: --to-latest로 풀어야 새 배포가 트래픽 받음
6secret key → Secret Manager, publishable key → 환경변수
70% 배포 → 스모크 테스트 → 전환을 워크플로로 자동화
8무중단 = 요청 확인 스크립트 실패 0건으로 증명
